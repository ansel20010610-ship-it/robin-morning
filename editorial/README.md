# 知更鳥晨間記事・製刊手冊

這份手冊給每天的排程編輯（Claude Code 雲端 routine）。本報每天台灣時間 07:30 出刊，**不允許缺稿**：除觀測站（無新進展時靜默）外，每一欄每天都要刊出。網站從 `main` 自動部署。

## 每班流程

1. **確認任務**：`python3 scripts/plan_day.py --group <班號>`。會印出刊期日期、期數、本班欄位、全刊狀態。已存在且驗證通過的稿件**不要重寫**（巴薩晨報的更新除外，見下）。
   **接第 1 班的正刊缺稿**（第 2、3 班；社長 2026-11-08）：第 1 班的經文、古典、牙周若到了 02:07 仍缺稿或驗證失敗，而且 `state/runs/<日期>.json` 沒有 `"1"`（第 1 班沒回報，多半是掛了），第 2 班做完自己的兩篇、回報之前接手寫；第 2 班也沒接到的，第 3 班開工就接。只接正刊三欄（devotion、music、perio），副刊仍由第 4、5 班補；照常讀手冊，模型照第 3 步分工表，第 8、9 步照做；推送前 `git pull --rebase origin main`，若該欄已在 origin/main 出現（第 1 班復活先推了），放棄自己的版本、不覆蓋。回報裡寫明接了哪一欄。
   **沒事就結束**：本班欄位都已存在且驗證通過，而且沒有其他任務（第 2、3 班的「接第 1 班的正刊缺稿」、第 4 班的觀測站與巴薩更新、第 5 班的補位、巴薩更新與「觀測站未查核」那一行、備稿班的庫存另計），就直接做第 11 步班次回報後結束，不必再讀規則檔——每次讀完整份手冊都很耗額度。plan_day 若印出「設定錯誤：」，不要寫稿，在回報第一行照抄給社長。
2. **讀規則**（每次都讀，不憑記憶）：`editorial/STYLE.md`（先讀第〇、一節：聲音與機器腔黑名單）、`editorial/SCHEMA.md`、`editorial/IMAGES.md`、`editorial/LESSONS-short.md`（編輯部教訓，過去反覆出現的錯，一條一行；含出現位置的全文 `LESSONS.md` 只有稽核讀）、`editorial/columns/<欄位>.md`，以及 `editorial/examples/` 裡最接近本欄的一篇範文（新聞類看 football.md，學術類看 perio.md，其他看 philosophy.md）。
3. **分工**：本班有兩篇以上時，用 Agent 工具為每一欄各派一個子代理**同時**撰寫。給子代理的指示要包含：專案路徑、日期、欄位、要先讀的規則檔、第 4–7 步、只寫自己那一個檔、不要 git commit。 **先替每篇指定文體**（`STYLE.md` 〇之四：跑 `python3 scripts/forms.py` 看最近各欄用過什麼，同一期不重複、同一欄不和前一篇相同、`scene` 一期最多一篇），聲腔照〇之四的記者表（每欄固定一位記者），粗體照〇之五（2–5 處），都寫進指示，子代理寫進稿件的 `"form"` 與 `"voice"`。你負責第 8–10 步。第 5 班一律平行。
   **模型分工（額度有限，照表指定，不要全部用最強的模型）**：用 Agent 工具派子代理時，一律帶 `model` 與 `effort` 參數：

   | 工作 | model | effort |
   |---|---|---|
   | 寫稿：牙周（perio）、文明（civilization）、哲學（philosophy）、文學（literature）、走進一件作品（artwork）、經典何以不朽（canon）、從零理解一個概念（concept）、詩（poem）、謎題（mystery） | `opus` | `high` |
   | 寫稿：巴薩晨報、古典、古蹟、不在計畫裡的知識、三個觀測站（FM、寰宇片場、訃聞） | `sonnet` | `high` |
   | 連載翻譯（serial，連載班）：譯者 `opus`／`high`，雙語核對 `sonnet`／`high` | — | — |
   | 世界與台灣快訊（news：審稿要做，不做第 9 步；沒有備稿） | `sonnet` | `high` |
   | 今日經文與禱告（devotion，只有經文與禱告，不審稿、不做第 9 步） | `sonnet` | `medium` |
   | 審稿（第 8 步）：牙周（perio，含備稿）——錯的是社長的專業，每週稽核發現日常審稿漏掉的不少（2026-11-04 起） | `opus` | `high` |
   | 審稿（第 8 步）：其他欄位 | `sonnet` | `high` |
   | 總編重寫（第 9 步；**只在審稿判定「重寫」時**，2026-11-08 起） | `opus` | `high` |
   | 忠實度核對（第 9 步，每篇必做） | `sonnet` | `medium` |
   | 依審稿意見修正、查單一資料、其他雜務 | `sonnet` | `medium` |

   班次本身（協調、跑程式、推送、回報）由排程設定的模型執行，不另派子代理去做。
4. **查重**：`python3 scripts/ledger.py --column <欄位>`、`python3 scripts/ledger.py --images`（已含備稿用過的主題與圖片）。
5. **研究與核對**：用 WebSearch、WebFetch 找原始來源。數字、日期、人名、引文都要能在來源找到，找不到就不寫。雲端的 WebSearch 結果常混入內容農場：搜尋時盡量用 `allowed_domains` 限定可信網域，或直接用 WebFetch 打開已知來源。注意：`allowed_domains` 裡只要有一個網站封鎖了我們的抓取程式，整次搜尋就會報錯（400 “not accessible to our user agent”）——遇到這個錯誤就把該網域拿掉重搜，不要放棄搜尋；已知不可用的網站列在 `columns/football.md`。
6. **找圖**：`python3 scripts/commons.py --search "<關鍵字>"`、`python3 scripts/commons.py "File:<檔名>"`。依 `IMAGES.md`。
7. **寫稿並驗證**：照 `STYLE.md` 第七節：先寫事實清單 `/tmp/robin/<日期>-<欄位>.facts.md`（一條一句，標 sources 項目，引文原文照抄），再從清單寫稿，寫完讀出聲改掉機器腔。正文定稿後寫 `brief`（見 `STYLE.md` 第六節）。寫到 `content/issues/<日期>/<欄位>.json`，跑 `python3 scripts/validate.py <日期> --column <欄位> --check-urls`，修到沒有 ERROR；黑名單、跨篇重複、標籤、引文數量的 WARN 一律改掉。
8. **審稿（必做）**：每篇另派一個**新的**子代理當審稿編輯，不可由寫稿者自己審。給它稿件與事實清單，指示它：以懷疑的態度核對至少 8 個關鍵事實與所有直接引文（打開原始來源逐字比對）、用 `commons.py` 核對每張圖的授權與圖說、逐條檢查欄位規格、找出把推論寫成事實的地方；檢查「今天、昨晚、本週末」等相對時間是否從刊出日早上讀者的角度成立（稿件常在前一天寫好）；核對 `brief` 的每一個事實都在正文裡、數字一致、沒有推論。核對粗體（〇之五）：2–5 處，標的是關鍵句與第一次出場的人事物，不是形容詞；零粗體或滿篇粗體都要回報。核對稿件 `form` 與骨架相符、`voice` 是該欄記者而且文筆像（〇之四）：清單就是編號段落、問答的小標是問句、一氣就沒有小標；讀三段認得出這欄的記者；不符算重大問題。另外做**零背景試讀**（STYLE.md 〇之三）：先當一個對題目毫無概念的讀者（只懂巴薩和牙周基本功）逐段讀，回報第一個跟丟的段落、哪些人名／術語／前情被當成已知、前三段有沒有交代這是誰／什麼／什麼時候／為什麼要講；前三段就跟丟是重大問題。另外做**聲音檢查**（STYLE.md 第〇、一節）：列出仍然像機器寫的句子（黑名單、段尾金句、預告、設問自答、假互動、定時插入的「我覺得」、替原作者打分數、出處書目化、查證流水帳），以及你讀到最想跳過的三段和原因。另做**白話檢查**（STYLE.md 第〇節「白話」，社長 2026-11-10）：列出不夠白話的句子（一句塞好幾件事、括號解釋、書面詞、翻譯腔、一段數字名字太多），每句附一個白話的改法；這類意見屬於「修正即可」，逐句照改，不單獨構成重寫的理由。**最後一題（社長 2026-11-06）：整篇像不像一個人寫給朋友看的？** 文體與腔調都對但讀起來像填表、像詞條、像考卷，算重大問題，要回報並指出是哪幾段。**經典何以不朽（canon）另加一題**：只讀標題、dek 與前 200 字，能不能用兩句話說出這件作品為什麼是經典？讀完全文，這個答案有沒有被證據撐起來，還是只剩製作趣聞和別人的差評？答不出來就是重大問題，要回報。只回報有證據的問題，不改檔案。
   **報告最後一行寫判定**（2026-11-08 起，第 9 步靠它決定要不要總編重寫）：有任何一項重大問題——零背景試讀前三段跟丟、文體或記者腔不符、整篇像填表／詞條／考卷、經典說不出經典在哪、像機器寫的句子三句以上或段尾金句成了結構——就寫「**判定：重寫**」並點名是哪幾段；其餘意見都是可以逐條改的（事實、引文、圖說、相對時間、brief 的一個數字、一兩句機器腔），寫「**判定：修正即可**」。
9. **修正、總編重寫、忠實度核對**：
   - **修正事實**：審稿的事實意見每一條先自行核實證據，成立才改，並同步改事實清單與 sources。聲音意見**不要逐條打補丁**（逐條補只會多出但書和孤兒段落），交給下一步。
   - **總編重寫**（**審稿判定「重寫」才做**；2026-11-08 起，之前每篇必做，佔了每天 Opus 運行的一半，而重寫帶進的漂移又要靠忠實度核對清掉）：另派一個**新的**子代理，給它事實清單、目前的稿件、審稿的聲音意見，請它先讀 `STYLE.md` 第〇、〇之三、一、三節和一篇範文，然後**從事實清單把整篇重寫一次**（照稿件 `form` 的文體與該欄記者的腔（`voice`）重寫，不得換成現場式或白描式；前三段要把讀者安頓好，背景句從清單的「讀者需要的背景」取材）：不逐句修改舊稿；可以刪、重排、換說法、重寫 title、dek、brief；不准新增清單以外的事實、數字、人名、引文，也不准新增但書；**也不准為了畫面感補細節**：清單沒寫的形容（「很安靜」「輕輕」）、動作、位置、心理狀態、因果連接（「於是」「這條街的起點是」）一律不寫；`quote` 的 text 與 original 原樣保留或整段刪掉，cite 只可刪掉「本文自譯」；非文字區塊（圖、表、資料卡、論文卡、經文、禱告、戰術圖）原樣保留；`topic_key`、`hero`、`sources` 不動（可刪掉不再用到的來源）。刪減後低於欄位字數下限沒關係（字數 WARN 在這一步可以忽略），寧可短而好看。寫完自己讀出聲校一遍，跑 validate。
   - **判定「修正即可」時**：不派總編重寫。依審稿意見修正事實（上一項），一兩句機器腔就改那幾句，然後直接進忠實度核對。審稿判定不清、或你讀審稿報告覺得問題其實是整篇的（意見散在五段以上、都是同一種毛病），就當作「重寫」。
   - **忠實度核對**（每篇必做，不論重寫與否）：再派一個**新的**子代理，逐句比對定稿（重寫稿或修正稿）與事實清單，列出清單裡沒有、或被改動的事實、數字、日期、人名與引文，把推論寫成事實的句子，以及改寫時添上去的修辭細節與因果。你把這些刪掉或改回，再跑一次 validate。
   - 第 5 班補稿在 06:45 以後、或巴薩晨報只是小幅更新（改動不到兩段，而且比分與頭條沒變）時，可以略過第 9 步。巴薩晨報的**賽後版一律走完第 8、9 步**（審稿、依判定重寫或修正、忠實度核對）：比分、頭條或開頭換了就是賽後版，不算小幅更新（11-04 第 4 班略過了，不要再略過）。
   - **比賽夜的巴薩晨報只走一條完整鏈**（2026-11-08 起，`columns/football.md`「比賽夜」）：巴薩在刊出前那一晚有比賽（開球在前一天 18:00 到當天 07:00 台灣時間之間）時，第 3 班的初稿只做審稿、修正事實、validate，不做第 9 步——三小時後的賽後版會把整篇換掉；第 4 班的賽後版照上一條走完整鏈。沒有比賽的夜晚，初稿照常。
10. **立刻推送**（每完成一篇就推一次）：
    ```
    git add content/issues/<日期>/<欄位>.json state/
    git commit -m "<日期> <欄位>：<標題>"
    git pull --rebase origin main
    git push origin HEAD:main
    ```
    直接推到 `main`，不要開分支或 PR。push 失敗就 `git pull --rebase` 後重推，最多三次。

11. **班次回報（必做，最後一步）**：不論本班寫了幾篇、是否順利，結束前都要執行
    ```
    python3 scripts/report_run.py --group <班號> --note "<一句話：做了什麼、有什麼問題；第 9 步的篇數，例如「重寫 1／修正 2」>"
    git add state/runs && git commit -m "<日期> 第 <班號> 班回報"
    git pull --rebase origin main && git push origin HEAD:main
    ```
    07:45 的監看會檢查第 1–5 班、演出班、連載班都有回報；沒有回報代表該班沒跑完或推送失敗，會開 issue 通知社長。備稿班用 `--group reserve`，演出班 `--group concerts`，連載班 `--group serial`，週日補刊 `--group late`。
    **推送被拒（例如 403、沒有寫入權限）時**：不要只把修補檔留在對話裡，要在回報與結尾訊息的第一行寫明「推送失敗：<錯誤訊息>」，讓社長立刻看到。

    **手機通知（PushNotification）只在需要社長動手時才發**：推送被拒、07:05 仍有欄位缺稿且無備稿可補、同一個錯誤反覆出現而本班修不好。一句話寫明問題與要他做什麼。一切正常、或問題已自行解決，就**不要**發——各班都在深夜到清晨執行，例行的完成通知只會吵醒他。

## 備稿班

**先看今天的快訊**（社長 2026-11-08）：不是週日（週日的缺稿歸週日補刊）時，跑 `python3 scripts/plan_day.py --date <今天>`（傍晚的預設日期是明天，一定要帶 `--date`）；「缺稿：」裡有 `news`（快訊沒有備稿，早上寫不出來就整天空著），先照 `columns/news.md` 補寫今天的「天亮以前，世界與台灣」：時間窗照舊從前一篇快訊起算，相對時間以讀者傍晚讀到為準，`updated_at` 填實際時間；sonnet／high 寫稿，另派審稿子代理逐則開網址核對，不做第 9 步；`python3 scripts/validate.py <今天> --column news --check-urls` 沒有 ERROR 就 commit「<今天> news：傍晚補寫」推送。這一篇不算進備稿的 2 篇額度。其他欄位的缺稿不在這裡補（早上已由備稿補位處理）。

依 `RESERVE.md`。先跑 `python3 scripts/reserve.py` 看各欄庫存；它列為「需修正」的備稿（有 ERROR，或不合現行規格：缺 form／voice、機器腔、出處類標籤、分類詞小標、沒有粗體、過期字眼）**不算庫存，先修這些再寫新稿**。只缺 form／voice、或只有一兩處機器腔或過期字眼的（「依我看」「換我」「目前」「最近」），讀一遍，照 `forms.py` 給它該欄沒用過、而且和它的骨架最接近的文體代號，填該欄的記者代號，改掉那幾個字，就算修好，不必重寫、不計入當天的 2 篇，當天能修的都修（2026-11-08 全部 23 篇備稿都沒有 form／voice）；整篇是舊規則的（「我的讀法」「重點來了」、出處類標籤、分類詞小標）才從庫存稿的正文與 sources 重建事實清單，依第 9 步派總編重寫（帶 forms.py 指定的 form 與該欄的 voice）。每天 2 篇的額度先用於修稿。然後只補它列為「不足」的欄位（正刊每欄 2 篇、副刊每欄 1 篇），從庫存最少的開始，每次最多寫 2 篇，全部達標且沒有需修正才直接回報結束，流程同上（含審稿子代理），驗證改用 `python3 scripts/validate.py --reserve --check-urls`，推送訊息用「備稿 <欄位>：<標題>」。

- 改 `content/config.json`（開欄、停刊、輪值）之後跑 `python3 scripts/validate.py --config`：排漏、排錯、日期不合法都會列出來；plan_day 遇到設定錯誤會停下，publish.yml 的驗證步驟也會報。
- 不讀取、不推測讀者的私人生活；不使用讀者自己的小說設定。
- 不使用 AI 生成圖片。不呼叫任何需要付費的 API。
- **不把社長的任何個人資料送出去**：email、姓名、帳號、git 設定裡的資料，都不可以放進請求的標頭、網址或內容。有些館藏 API 要求在標頭附聯絡方式（例如芝加哥藝術博物館的 `AIC-User-Agent`），一律只寫 `robin-morning (https://github.com/ansel20010610-ship-it/robin-morning)`，也就是 `scripts/common.py` 的 `UA`。派子代理時把這一條寫進指示。

## 發生問題時

- 單篇卡住（來源不足、圖找不到）：換一個題目重寫，不要放棄這一欄；真的來不及，交給下一班或備稿補位，並在回報中說明。
- 觀測站查核失敗：依欄位規格寫 `undetermined` 短稿。
- 時間不夠：已完成的先推上去。
