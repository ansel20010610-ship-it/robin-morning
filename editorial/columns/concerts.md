# 近期演出（concerts）｜常設，每天早上和當期一起更新

## 社長的規格（2026-10-31）
台灣近期的交響樂、歌劇、音樂劇等演出資訊，台中為佳，台北、高雄也可，附上「值得聽」評分。放在首頁最下面當常設欄，有新消息就加進去。

## 這一欄是什麼
不是文章，是一份清單：`content/concerts.json`。它不屬於任何一期，也不進刊期驗收。
App 把它放在首頁最下面，另有完整頁面 `#/concerts`。演出日一過，App 就不再顯示；檔案由 `prune` 清掉。

讀者：台中執業的牙醫，聽古典樂，喜歡主流必聽名作（見 `editorial/music-canon.md`）。他要的是「哪幾場值得排進行事曆」，不是全台藝文活動表。

## 收什麼
- 交響樂、協奏曲、歌劇（西方歌劇；戲曲不算）、音樂劇、室內樂、重要的獨奏會與聲樂、大型合唱。
- **台中**：3 分以上都收。
- **台北、新北、高雄**：只收 4 分以上（值得專程跑一趟）；`fetch` 已先排除這三地主廳以外的場地。
- 不收：學生、教師、社區團體的成果發表與期末音樂會；動漫、電玩、電影配樂拼盤；流行歌手與跨界演唱會；兒童劇；戲曲；講座與工作坊；只是在名稱裡用「交響」二字的商業秀。
- 拿不準的，看演出者有沒有職業水準的紀錄。

## 值得聽（3–5 分，整數）
- **5**：年度級。難得來台的世界一線樂團、指揮、獨奏家或歌手，或國際大型歌劇院、原版百老匯／西區的完整製作。
- **4**：值得專程跑一趟。
  - 國際知名獨奏家或室內樂團。
  - 國內頂尖職業樂團（國家交響樂團、國臺交、北市交、長榮、高市交）由重要指揮或獨奏家帶主流名作。
  - 國外職業樂團或歌劇院樂團來台演出完整的主流名作，例如年底的貝九（社長 2026-11-09：為啥近期演出沒有 12/27 貝九）。
  - 完整製作的歌劇；有份量的本地原創音樂劇。
- **3**：人在台中值得去。國內職業團隊的常規音樂會、有份量的獨奏會與室內樂、完整的本地音樂劇製作。
- 2 分以下不收。
- 評分只看演出者、曲目與製作本身；宣傳文案的形容詞（「頂尖」「震撼」「史詩」）不算證據。
- 同一份清單裡 5 分要少，一個月一兩檔就算多。

## 每天的流程（演出資訊 routine，台灣時間 06:17，要在 07:30 出刊前推完）
1. `python3 scripts/concerts.py prune`：清掉已經演完的場次。
2. `python3 scripts/concerts.py fetch`：從文化部藝文活動開放資料抓新候選，存成 `/tmp/robin/concert-candidates.md`。
   - 印出「查核失敗」就跳到第 7 步。
   - 印出「開放資料這次不完整」時，已列入的演出不必逐筆去查售票頁，照常處理新候選。
3. 讀 `content/concerts.json` 與候選清單。逐筆判斷收不收：先刷掉明顯不收的（見上），剩下的才查。
4. 要收的，查演出者與曲目：先用 WebFetch 讀候選清單附的 OPENTIX 或場館節目頁，必要時再查場館官網（臺中國家歌劇院 npac-ntt.org、國家兩廳院 npac-ntch.org、衛武營 npac-weiwuying.org）或樂團官網。
   - 查不到演出者與主要曲目的，這次先不判，明天會再出現。
5. 寫進 `content/concerts.json`（格式見下）。
   - 同一製作在不同城市或不同售票頁的 UID（候選清單會標「可能是同一製作」），合併成一筆，`shows` 列出所有城市的場次，`uids` 列出所有 UID。
   - 已列入的演出若有新場次、新城市或售完等消息，更新那一筆，不新增。
6. `python3 scripts/concerts.py close --reject <UID>=<分數與理由> …`：不收的每一筆都寫分數與理由。
   - 沒寫理由的不會記成不收，明天會再出現；還沒判完的就這樣留著。
7. `python3 scripts/validate.py --concerts`，有 ERROR 就修，WARN 也改掉。然後推送（見 routine 指示）。
8. **補查（每兩天一次）**：先跑 `python3 scripts/concerts.py sweep-due`，印出「今天要做」才做（社長 2026-11-08：每兩天跑一次）。
   - 它會列出十個來源、證據檔的格式與收尾指令，照它印的做。開放資料不收的大型製作靠這一步。
   - **看到的每一檔都要評分**：符合收錄門檻的一律加進來，`uids` 用空陣列。
   - 世界一線樂團、指揮與獨奏家通常是 5 分，台北、高雄場也收。
   - 07:15 前做不完就停。連不上或來不及查的來源照實寫進證據檔，照樣跑 `sweep-done`：它會存下來、算沒做完，明天再輪到。
   - `state/concerts/` 一起 commit。

## 格式（`content/concerts.json`）
```json
{
  "checked": "2026-11-01",
  "events": [
    {
      "id": "rattle-brso-2026",
      "title": "拉圖與巴伐利亞廣播交響樂團",
      "kind": "交響樂",
      "rating": 5,
      "why": "（一到兩句：為什麼值得聽）",
      "who": "賽門．拉圖（指揮）、巴伐利亞廣播交響樂團",
      "program": "台中場：拉赫曼尼諾夫《第三號交響曲》、舒伯特《第九號交響曲「偉大」》",
      "price": "NT$…（查到才寫）",
      "note": "（可省略）",
      "shows": [
        { "date": "2026-11-16", "time": "19:30", "city": "台中", "venue": "臺中國家歌劇院大劇院", "tickets": "https://www.opentix.life/program/…" }
      ],
      "added": "2026-10-31",
      "uids": ["6a68e15526b32427d06042d2"],
      "sources": [{ "title": "OPENTIX 節目頁", "url": "https://www.opentix.life/program/…" }]
    }
  ]
}
```
- `id`：小寫英數與連字號，例如 `rattle-brso-2026`、`cosi-ntt-2026`。
- `title`：30 字內，去掉系列名、贊助商與年份（「2026 NTT遇見巨人」「力晶2026藝文饗宴」都拿掉）；外國人名用通行中譯。
- `kind`：交響樂、協奏曲、歌劇、音樂劇、室內樂、獨奏、聲樂、合唱、其他。
- `shows[].city`：台中、台北、新北、高雄。`time` 是開演時間（HH:MM）。`tickets` 填該場的售票頁。
- `who`、`program`、`price`、`note` 可省略；查到才寫，不猜。不同城市曲目不同時，`program` 寫明是哪一場的。
- `note`：30 字內的票況或提醒（「已售完」「11 月 5 日 12:00 開賣」「演前 40 分鐘有導聆」）。
- `added`：第一次列入的**台灣日期**。`close` 與 `sweep-done` 會把這次新加的自動改成今天；之後更新同一筆時不改。

## `why` 怎麼寫
15–80 個中文字，一到兩句，照 `STYLE.md` 第〇節的聲音。
- 第一句就是這場最值得聽的那件具體的事（誰、演什麼、為什麼難得），可以有判斷，要押得起。
- 「多年沒排過」「首度來台」這類說法要查得到才寫。
- 不寫宣傳腔（「不容錯過」「震撼登場」「頂級饗宴」「史詩級」），不寫「本場音樂會將……」，不替讀者設想反應。
- 作者沒有身體：不寫「我聽過他的現場」。

## 不可以做的事
- 只寫 `content/concerts.json` 與 `state/concerts/`。不動 `content/issues/`、其他規則檔、程式與 App。
- 不編造場次、曲目、演出者、票價。開放資料、節目頁與場館頁對不上時，以場館或售票頁為準，拿不準就不寫那一項。
- 抓資料時不偽造瀏覽器的 User-Agent；`scripts/common.py` 的 `UA` 就夠用。不把社長的任何個人資料放進請求。
