# 後院的明信片（postcards，編輯部簡稱「地圖班」）｜快用完才加新城市

## 這是什麼

後院（特供版）的知更鳥會出國旅行，旅行時每天寄一張手繪明信片回家（`assets/nest.js` lifeOf、`assets/postcard.js`）。每張明信片畫一個城市的一個著名景點，一眼要看得出是哪裡；社長不要真實照片、不要台灣的景點，也不要「幾張在輪」（2026-11-10）。開頭有三十個國外城市，每個六個景點。

鳥一年大約出國十七、八趟，三十個城市不到兩年就會去完一輪。社長說要「想辦法繼續生新景點和新國家」，又說「不用每週畫城市，快用完再畫」（2026-11-10）。所以地圖班**每週只檢查一次**：社長的院子還有幾個城市沒去過（`python3 scripts/postcards.py demand`，用 App 自己的 nest.js 從院子的餵食紀錄算，跟手機上一模一樣）。**超過 6 個就什麼都不做直接結束**；剩 6 個以下才畫**一個**新城市（六個新景點）。新城市一加入，下一趟旅行就會先去那裡（lifeOf 先挑沒去過的城市），鳥一趟約三週一次，剩 6 個時還有好幾個月，每週補一個綽綽有餘。

## 機器

- 每個城市的圖和字寫在 `state/postcards/parts/` 的一個檔案裡（一個檔可以有好幾個城市，地圖班每次新增一個檔，一個城市）。檔名 `YYYY-MM-DD-<城市id>.js`，**按檔名排序**，新城市永遠排在最後。
- `python3 scripts/postcards.py check`：跑每個景點的四季、檢查字數、標點、六個景點、沒有台灣。
- `python3 scripts/postcards.py build`：檢查後產生 `assets/sights.js`（所有圖與字，App 打開明信片時才下載）和 `assets/cities.js`（城市清單，nest.js 用）。**不要手改這兩個檔。**
- `python3 scripts/postcards.py sheet <城市id>`：把那個城市六個景點的夏天、冬天各畫一張，存成 `state/postcards/sheet.svg`（有轉檔工具時另存 `.png`：`rsvg-convert`，或 `pip install cairosvg`）。**用 Read 打開 PNG 親眼看**，確認每張一眼認得出是哪個景點。
- `python3 scripts/postcards.py list`：已有的城市與景點、各自加入的日期。
- `python3 scripts/postcards.py demand`：社長院子的進度（院子代碼在環境變數 `NEST_CODE`，不寫進 repo）。印出「OK」就是還夠；印出「LOW」並以 3 結束就是要畫。讀不到（網路、共用儲存沒有讀取入口）就不畫，在回報裡寫原因。

## 一個城市檔的格式

```js
var CITIES_PART = {
  lisbon2: {                       // 城市 id：小寫英文字母，不能和已有的重複（先跑 list）
    zh: "里斯本", de: "Lisboa",      // 台灣讀者熟悉的中文名；當地語言的拉丁字母寫法
    gift: "一片藍白磁磚",            // 鳥帶回家的紀念品，一個小東西
    added: "2026-11-19",            // 加入旅行的日期：commit 當天的**後天**（讓每支手機先更新）
    sights: [
      { id: "tram28", zh: "28號電車",
        see: ["黃色的電車爬上很陡的坡", "…", "…"],     // 三句鳥看到的事，12–30 字，不加句號，寫得具體、溫和、不出錯
        spots: ["電車的車頂上", "…"],                 // 兩三個鳥停的地方（名詞片語）
        draw(c) { const { r, sea } = c; let s = ""; const perch = []; /* … */ return { s, l: "", perch }; } },
      // 一共六個景點
    ],
  },
};
```

畫圖的規則（照 `assets/pc-kit.js` 的工具和已有城市的畫法，同一種風格）：
- 畫布 300 × 200。天空、太陽、雲、天氣、紙紋、手繪的抖動都由 postcard.js 加，**只畫景**：地面、水、建築、地標、樹、小道具。
- 地平線大約在 y 140–175；上面 40% 是天空，左上角要留空（城市名印在那裡），右上角也留空（郵票）。主要地標放在中間或中間偏右（x 120–260），大到在 156 px 寬的縮圖上也認得出。
- `c.r()` 是這張卡的亂數：用來微調地標的位置與大小（±10–15%）、要不要多一艘船、一面旗、樹的位置。`c.sea` 是季節：樹用 `tree(x, y, 大小, sea, r)`，冬天可在屋頂加雪。**一律白天**（社長：不用日夜），`l` 永遠是 `""`。
- 只用 path、rect、circle、ellipse、polygon 與 fill/stroke 屬性；不用文字、圖片、class、style、濾鏡。數字用 `f1()` 四捨五入。
- `perch`：兩三個鳥（約 16 px）可以站的點，`[x, y]` 是腳的位置：塔尖、屋脊、橋欄杆、路燈。
- 每個景點要是那個城市**最有名、最一眼認得出的輪廓**；同一城市的六個景點不能看起來一樣。

## 每週的流程

1. `git pull`。`python3 scripts/postcards.py demand`。**印出 OK 或讀不到，就直接寫三行回報後結束**，不讀其他檔、不畫。
2. 印出 LOW 才往下做。`python3 scripts/postcards.py list` 看已有的城市。
3. 選一個還沒有的城市：國外（**不要台灣**）、讀者會想去、有六個辨識度高的景點、和已有城市不同的地區優先（已有很多歐洲城市，就選亞洲、美洲、非洲、大洋洲）。候選例：大阪、奈良、釜山、曼谷、河內、新加坡、峇里島、吳哥窟、杜拜、耶路撒冷、佩特拉、馬拉喀什、開普敦、里約熱內盧、布宜諾斯艾利斯、馬丘比丘、墨西哥城、溫哥華、芝加哥、紐奧良、波士頓、皇后鎮、墨爾本、塞維亞、波爾圖、克拉科夫、杜布羅夫尼克、卡帕多奇亞、奧斯陸、赫爾辛基、愛丁堡以外的英國城市……一次只做一個。
4. 用一個子代理（Opus/high；畫圖要眼力）照上面的規則畫六個景點、寫字，存成 `state/postcards/parts/<今天>-<id>.js`，`added` 寫今天的後天。
5. `python3 scripts/postcards.py check` 到 0 problems；`python3 scripts/postcards.py sheet <id>`，打開 PNG 看。認不出是哪裡的景點，退回去重畫（最多兩次）；兩次還不行就換一個更好畫的景點。
6. `python3 scripts/postcards.py build`。
7. 只 commit 這三個路徑：`state/postcards/parts/<新檔>`、`assets/sights.js`、`assets/cities.js`。訊息：「地圖班：加入<城市>（<六個景點>）」。push。
8. 不碰其他檔案，不改 nest.js、postcard.js、pc-kit.js；**已有的城市檔一律不改**（改了會讓已經寄出的明信片變樣）。發現舊城市畫錯，寫在回報裡讓社長的編輯處理。

## 為什麼這樣排

- 每個城市都記下加入的日期（`added`），nest.js 只讓那天已經有的城市被選中，所以加新城市不會改變任何已經發生的旅行、已經寄出的明信片。
- 新城市在 commit 的後天才加入，每支手機有一天多的時間拿到新的 `cities.js`。
- 一個城市六個景點，一趟旅行最多五天，所以一趟裡每天的景點都不同；下次再去同一城市，接著看上次沒看到的。
